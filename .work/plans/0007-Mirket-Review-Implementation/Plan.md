## 1. Harden the pre-commit hook, then fix command recognition

1. Reproduce both audit findings at the hook boundary in `tests/test_cleanup_hooks.py`: a command-selected executable or config reaches the current probe, and a single quoted punctuation argument can cause a compound-command denial. Use mocks or harmless local sentinel programs; do not execute any proposed commit. Confirm normal `git -C`, acknowledgement, and exact exception cases as controls.
2. In `plugins/mirket/hooks/cleanup.py`, separate recognition, target resolution, and index inspection. For the supported direct syntax, derive only literal target-selection data (starting with `cwd` and `-C`). Invoke a trusted, absolute Git executable independently of the command’s executable, PATH, or wrappers; do not run the submitted shell or replay arbitrary options and assignments. Reject path-qualified lookalikes, command-local PATH changes, arbitrary `-c`/`--config-env`, and ambiguous Git environment or index selectors rather than silently checking another repository. Support commit modes that use the current index unchanged. For recognizable `-a`/`--all`, `--include`, `--only`, or pathspec commits, give a clear unsupported response with an explicit-staging retry where appropriate. Keep the existing exact exception and fail-closed behavior for recognized commits whose index cannot be inspected.
3. Make the probe use fixed arguments and prevent repository or inherited configuration from running external helpers or triggering writes or network fetches. Check Git version compatibility before selecting the mechanism: Git 2.35.1 and older may treat `core.fsmonitor=false` as a hook path ([Git config](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corefsmonitor)); validate the supported floor or another safe disable mechanism. Check the diff options against [Git diff](https://git-scm.com/docs/git-diff). If the executable, version, environment, or target cannot be trusted, report the unsupported case without invoking a probe that could execute a helper. Verify H1 and H3 against disposable repositories.
4. Replace the lossy separator classification with a small recognizer that preserves quote and escape context. Keep ordinary direct commands and basic wrappers that can be interpreted without shell evaluation. Handle expansion, aliases, compound commands, heredocs, and other uncertain forms according to the explicit supported boundary; do not infer a target from ambiguous syntax. Update the lifecycle-hook README for the exact supported subset, error recovery, and host limitations. Verify H2 and rerun the hook suite before moving to Design.
