## Host enforcement

The final candidate ran through Codex CLI 0.167.0 and Claude Code 2.1.323. A local scripted model requested the same three shell calls. Both native hosts ran SessionStart and UserPromptSubmit, allowed the ordinary status check and denied the unacknowledged commit at PreToolUse. A second independent Git hook protected each disposable repository. HEAD stayed unborn and the staged content was identical afterward. The supported dry-run passed Mirket in both hosts. Claude completed it and the Codex workspace sandbox refused the Git index lock. An additional signed-in Codex run on the installed 0.5.1 release confirmed the same distinction. [Native events and tool results](Checks/NativeHooks.json)

Ordinary Codex hook review took place in the disposable profile. Reinstalling later changes to skill files marked the package modified and required renewed review. The final positive check used that reviewed revision. Four native Claude outage probes requested only an ordinary status check. It ran after either a synthetic failure or timeout under the default policy. Applying the host’s blanket blocking option to the test hook stopped the read in both cases. The repository keeps the shared matcher and existing outage policy. Claude’s normal account was signed out. Its real session reached both startup hooks, then requested login before inference. Model-selected Claude routing, long-running compaction and real-workload latency remain unmeasured.
