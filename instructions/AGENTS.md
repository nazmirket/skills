# Mirket working instructions

- Apply **Execute** throughout. Read the project's instructions and current state. Choose one Mirket skill to own each requested outcome and name selected skills in lowercase backticks. When ownership is unclear, use the active plugin's `skills/execute/references/Routing.md`. If Mirket is unavailable, say so and continue within existing authority.
- Before the relevant step, read the owner's applicable guidance. When it points to an index, follow the matching entry to the procedure and use its checks. Reuse guidance already in context. Add a supporting skill when it can resolve a distinct question.
- Use **Author** for writing and issue triage, **Market** for marketing claims and **Ship** for product requirements. Keep product and business decisions with the human. Preserve project conventions and user changes.
- Use **Plan** for substantial implementation. Follow `skills/plan/SKILL.md#coordinate-workers` when delegation is authorized and supported. Keep routine work direct.
- Apply `skills/code/references/EngineeringPractices.md` to software changes and code reviews. Use **Architect** for lasting design choices and threat modeling, **Audit** for security and privacy review, and the implementer for authorized hardening.
- Follow `skills/execute/references/Workspace.md` for workspace policy, ADR placement, and numbering. Before the first project write in a Git worktree, verify the effective ignore rules and preserve the project's privacy policy. Put scratch output in `.work/temp/<task>/` and deliver artifacts to their designated paths.
- Use **Migrate** for persistent-state transitions and **Deploy** for rollout, service health and recovery. For release preparation or authorized publication, follow `skills/execute/references/VersionedDistribution.md`. Verify authority for the candidate and target at each stage.
- Run focused and required checks. For visual checks, inspect the verified full-resolution original under `skills/design/references/tools/Screenshot.md`. Apply **Clean** before delivery of edits or artifacts and before an authorized commit. Preserve unrelated work and important records.
- Take the simplest complete path. If an attempt fails again for the same reason, change approach. Continue independent work when a prerequisite is missing. Report the result, supporting evidence and material limits.
