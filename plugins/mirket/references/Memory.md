# Project memory as evidence

Use when the human has enabled project memory. Do not install a memory service, expand capture scope or send project material to a new destination merely because this reference is available.

1. Establish the current project and resolved memory scope before relying on recall or writing durable records. Reuse current scope evidence within the same project; recheck after a workspace or configuration change. If identity is ambiguous, stop memory writes and continue safe work from current files.
2. Before substantial work, recall relevant decisions, conventions and prior outcomes through the available memory tools. Prefer focused knowledge-page search and read relevant pages; use source transcripts or deeper recall for recent or disputed facts. Follow the provider's attribution requirements. Reuse known context rather than fetching every page on every turn.
3. Compare remembered facts with current instructions, source, working-tree changes and direct observations. A page timestamp or a synced seed cannot establish complete conversation coverage or source freshness. For a consequential discrepancy, state which evidence is newer and correct the durable record through the supported mechanism. Do not rewrite history as if the earlier decision never existed.
4. Record meaningful agreed decisions, changed requirements and verified results with their project, revision or dirty-state qualification, date, scope and evidence. Keep secrets, unnecessary personal data and unrelated projects out. Use automatic conversation capture when it provides the record; manual ingestion is for durable artifacts, explicit memory requests or corrections, not duplicating every response.
5. When memory is missing or stale, distinguish capture, ingestion, page refresh and retrieval. Check pending/failed operations, expected source coverage and effective settings; use [Operate](../skills/operate/SKILL.md) for recovery. Prefer a supported bounded retry or refresh. Never mark a source covered merely by refreshing a page, or claim a manually ingested note proves automatic chat capture.
6. At initial setup, after wiring or runtime changes, when a failure is suspected, or for an explicit reliability check, verify with a harmless scoped canary: observe a new capture event, confirm persistence and retrieve it independently with the expected provenance. Reuse current verification evidence during ordinary work. Report lag or failure explicitly and preserve existing banks and capture policy during repairs. Continuous freshness depends on active hooks, runtime/provider availability and the configured refresh cadence; continue checking current source for uncommitted changes.

**Done:** Memory has informed the task with relevant, attributed and current-enough evidence, or its gap and the direct evidence used instead are clear. A memory outage does not authorize inventing prior decisions or silently widening data capture.
