# Translate a visual reference

Use to reproduce a supplied mockup or screenshot in [Design](../SKILL.md), or implement an agreed generated interface concept from [Imagine](../../imagine/SKILL.md). First establish whether the image is an exact target or inspiration. A single image describes one view; it does not establish responsive rules, interactions or business logic.

1. **Map the observable relationships.** Identify the screen, viewport, state and content. Trace section order, alignment, proportions, whitespace, type roles, color and surfaces, imagery and crop, and the action hierarchy. Note where observed assets or existing tokens can produce the intended result and where values are estimates.
2. **Mark what needs inference.** Distinguish visible, supplied or verified details from guessed values, unavailable assets, hidden behavior and other sizes. Use the existing product or authoritative files to fill gaps. Mark generated or unverified copy and data as placeholders; do not carry over invented product claims. Ask only if the unresolved difference changes the result materially.
3. **Build the relationships, not a flat image.** Reuse approved assets and real content. Match at the reference size first, then reflow based on hierarchy and content. Preserve semantic controls, access and required behavior. For a meaningful departure, record what changed and why; do not silently substitute a stock layout.
4. **Compare like with like.** Supply [Critique](../../critique/SKILL.md) the reference, inspected implementation, matched size, content and state, plus relevant other views. Distinguish a mismatch from a required departure. Use [Test](../../test/SKILL.md) for behavior the image cannot establish.
