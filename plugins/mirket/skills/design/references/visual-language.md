# Visual language

Use to make a visual direction coherent at the level of type, color, spacing, surfaces and imagery. Begin with established rules where they work. Make the smallest set of decisions that remains useful when content changes.

## Type sets the reading order

Assign roles to display type, headings, body, labels and data. Make adjacent roles distinguishable by a few deliberate changes in weight, size, spacing or position. Give long text a comfortable measure and line height; keep dense labels readable. Test real scripts, weights, fallback fonts, long labels and text enlargement. Use tabular numerals when aligned values help comparison. Check the type at actual viewing size; a zoomed canvas hides reading problems.

Avoid adding a font to create character that composition or imagery could express more reliably. Check availability and permitted use before committing to a font, especially for exports, multiple locales or custom web delivery.

## Color has a job

Set roles for foreground, background, surfaces, action, focus, feedback and data. Establish actual foreground and background pairs, including layers, images, hover, disabled and selected states. Check relevant contrast against [accessibility needs](adaptive-and-accessible.md); distinguish state through words, shape or position as well as hue. Keep color reserved for the level of emphasis it earns. A dark theme needs tuned pairs and surface relationships rather than mechanically inverted colors.

## Space shows relationships

Use proximity for belonging and larger intervals for transitions. Reuse a few spacing relationships where they help, and adjust for actual content and optical alignment. Establish clear edges and reading measure before refining margins or corner radii. A border can separate rows; a shadow can place a floating surface; a plain background can let the content carry its own boundaries. Avoid giving every group a container or every label a badge.

Choose density by task and device. Compact controls may serve repeated desktop operations, while touch actions and long-form reading need different spacing. Use separate layout treatments when one density rule would harm either.

## Images and details support the idea

Use actual product material, photography, illustration or data where it explains something. Select a crop that preserves the subject, scale and context, then check it at the final ratios. Protect text readability when it overlays media; reserve space for loaded imagery and choose a meaningful fallback when it fails. Do not represent a generated stand-in as a real product view, customer or result.

Use a coherent icon family and size stroke and detail for the rendered scale. Label unfamiliar controls; name icon-only controls in their accessible semantics. For illustration systems and exports, use [visual artifacts and assets](artifacts-and-assets.md). For temporal behavior and responsive feedback, use [motion and gestures](motion-and-gestures.md).

## Check the combination

Look at the design in a normal case, an adverse case and one nearby existing surface when relevant. Hide decorative treatment briefly: if the hierarchy disappears, repair the underlying type, spacing or structure. Put it back when it adds useful atmosphere, emphasis or continuity. Check actual output rather than judging isolated swatches or components.
