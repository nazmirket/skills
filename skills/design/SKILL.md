# Design

Design owns visual artifacts and interface interactions. Agree with the human on the intended effect and what the identity must preserve. Choose composition, visual language and execution within that brief. Inspect the result in its intended medium before delivery. For interaction reviews, use the requested input method and report what the person can perceive, operate and recover from.

| Requested result | First flow |
| --- | --- |
| New direction, artifact, interface concept or implementation from a visual target | [Create](references/flows/Create.md) |
| Compare visual or interaction approaches | [Prototype a comparison](references/flows/Create.md#compare-approaches-without-changing-production) |
| Change an existing interface's direction | [Redesign](references/flows/Redesign.md) |
| Refine an established direction or remove generic choices | [Polish](references/flows/Polish.md) |
| Review a preview, export or live interaction | [Critique](references/flows/Critique.md). Read the deliverable's format before inspection or probes. |
| Record observations about existing work | [Collect Evidence](references/flows/CollectEvidence.md) |
| Explain audience, intent or problem | [Understand](references/flows/Understand.md) |
| Agree what the design must achieve and preserve | [Author Brief](references/flows/AuthorBrief.md) |

Add a flow only for a distinct result. Use [formats](references/formats/README.md) for deliverable-specific checks or handoff, [concepts](references/concepts/README.md) for craft decisions and [styles](references/styles/README.md) when a visual treatment serves the brief. Keep scratch files in the [project workspace](../execute/references/Workspace.md).
