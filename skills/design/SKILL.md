# Design

Own the visual result and how people use the interface. For an interaction review, exercise the task with the requested input method and report what the person can perceive, operate and recover from. Agree with the human on the intended effect and what the identity must preserve; choose the composition, visual language and execution within those boundaries. Inspect the result in its intended medium before delivery.

| Requested result | Start here |
| --- | --- |
| New direction, artifact, interface concept or implementation from a visual target | [Create](references/flows/Create.md) |
| Compare visual or interaction approaches | [Prototype a comparison](references/flows/Create.md#compare-approaches-without-changing-production) |
| Change the direction of an existing interface | [Redesign](references/flows/Redesign.md) |
| Refine the established direction or remove generic choices | [Polish](references/flows/Polish.md) |
| Review a preview, export, or live interaction | [Critique](references/flows/Critique.md): read the deliverable's format before inspecting it or running a probe. |
| Record what is observable about the existing work | [Collect Evidence](references/flows/CollectEvidence.md) |
| Explain the audience, intent or problem | [Understand](references/flows/Understand.md) |
| Agree what the design must achieve and preserve | [Author Brief](references/flows/AuthorBrief.md) |

Start with one flow. Use the other flows only for a distinct result you need. Open the relevant [concepts](references/concepts/README.md) for craft decisions and [styles](references/styles/README.md) when a visual treatment serves the brief. Keep scratch work under the [workspace rules](../execute/references/Workspace.md).

Use a [format](references/formats/README.md) when the deliverable needs its own checks or handoff.
