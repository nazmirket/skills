# Translate a visual reference

Use to translate a supplied mockup or screenshot in [Design](../SKILL.md), or implement an [agreed generated interface concept](../SKILL.md#generate-an-interface-concept). Carry over hierarchy, tone, and relationships by default. Match literal details when the human explicitly makes them part of the target. A single image describes one view; it does not establish responsive rules, interactions, or business logic.

1. **Map the observable relationships.** Identify the screen, viewport, state and content. Trace section order, alignment, proportions, whitespace, type roles, color and surfaces, imagery and crop, and the action hierarchy. Note where observed assets or existing tokens can produce the intended result and where values are estimates.
2. **Mark what needs inference.** Distinguish visible, supplied or verified details from guessed values, unavailable assets, hidden behavior and other sizes. Use the existing product or authoritative files to fill gaps. Mark generated or unverified copy and data as placeholders; do not carry over invented product claims. Ask only if the unresolved difference changes the result materially.
3. **Build the relationships.** Reuse approved assets and real content. For an explicit match, check the specified details at the reference size first, then reflow based on hierarchy and content. Preserve semantic controls, access, and required behavior. Record meaningful departures from the agreed target.
4. **Compare like with like.** Inspect the implementation at comparable sizes, content, and states. Judge intent by hierarchy and tone, and judge literal details against the requirements that specify them. For substantial visual work, use the reference, brief, and actual preview in the [visual critique](../SKILL.md#visual-critique). Use [Test](../../test/SKILL.md) for distinct behavioral evidence.
