# Create visual work

Use for a new visual direction, a new artifact, or implementing a supplied visual target. Start with the request, real content, and the medium where the work will be used. If a reference changes an existing interface's design, use [Redesign](Redesign.md) for the live baseline and preservation rules before translating it. If a reference already settles the direction, go straight to translation.

## Set the direction

1. Identify the audience, intended effect, main action or idea, and what the identity must preserve. Inspect the project's own content, assets, conventions and approved decisions first. Use outside comparisons only when they can resolve an open direction or pattern. If the direction or constraints are still unsettled, use [Author Brief](AuthorBrief.md).
2. For an open direction, show two or three materially different approaches using comparable content and constraints. Identify what leads, what stays familiar, and what each approach does better. Resolve consequential direction or product choices with the human; reuse decisions already made.
3. Prove the consequential part first with a representative screen, state, crop, frame, or section. Use realistic material and mark placeholders. Pick the relevant [concept references](../concepts/README.md); use a [style reference](../styles/README.md) only when it serves the brief.

## Generate an interface concept

- Inspect the product and authorized references. A redesign must start with the live baseline. Get explicit agreement on the audience, main action, hierarchy, content, visual direction, target views and constraints before generating. Reuse agreement on the same brief; ask again only if direction, scope, or a material constraint changes.
- Generate the fewest views that answer the brief with an appropriate tool and approved inputs. Inspect the output against the brief, flag drift and placeholders, and show the direction. If the concept image is the deliverable, deliver it and stop.
- Proceed with a concept that fits only when the approved brief also authorizes implementation. If adopting the concept would change the direction or scope, ask first. Translate it with the procedure below.

## Implement a supplied visual reference

- Identify the reference's viewport, content and state. Map section order, hierarchy, alignment, proportion, type roles, color, surfaces, imagery and crop. Preserve hierarchy, tone and relationships by default; match literal details the human requires at the reference size first.
- Separate visible and verified details from inferred values, unseen states, missing assets and unknown behavior. One image does not establish responsive rules or business logic. Use actual content and approved assets; flag unverified copy or generated data and leave invented claims out.
- Preserve required behavior, semantic controls and access. Compare at equivalent content, size and state, then inspect important alternate views. Record meaningful departures from the agreed target.

## Compare approaches without changing production

When the result is a decision, name the uncertainty and the observable difference that would settle it. Build the smallest isolated comparison outside production. Hold content and unrelated dimensions steady and make the alternatives easy to switch or replay. Give the human the comparison and what it establishes, including any remaining uncertainty. Use the [shared prototype method](../../../../references/Prototype.md) for further guidance. Stop without adopting the prototype in production unless that was separately authorized.

## Finish

Deliver in the intended medium. Use the existing stack and carry the approach through the relevant states, formats and input methods. Inspect the actual result; for substantial work, follow initial inspection with a distinct [critique](Critique.md) and recheck material corrections. Return the artifact or working entry point, editable sources where useful, and material limits.
