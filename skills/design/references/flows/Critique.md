# Critique visual work

Use for a visual or interaction review, or to recheck substantial visual work against its brief. A review-only request ends with findings.

## Load the deliverable's format

Identify what is being judged. Use its format guide to choose the inspection criteria before running probes or assigning evidence collection. A web banner uses [Banner Design](../formats/BannerDesign.md) for its crop and legibility. An embedded 3D scene uses [Scene Design](../formats/SceneDesign.md) for scene behavior. A checkout dialog uses [Web Design](../formats/WebDesign.md) for the app flow. Use the [format index](../formats/README.md) for other deliverables. Add another format only for a distinct question.

## Inspect and report

1. **Establish the comparison.** Name the intended reader or user, task, brief, build and states. For a change, match baseline and revision by content, viewport, theme, zoom, input and state. Include the primary path and the adverse width or state most likely to change the verdict. For a design system, sample affected components in context.
2. **Check visual evidence.** Reuse full originals from the initial inspection when they meet the [capture standard](../tools/Screenshot.md) for this build, surface and state. Obtain missing originals where possible. Inspect the whole composition and read the actual pixels around findings. Keep matched full originals for change claims.
3. **Judge the design in use.** Where does attention land first? What should the person understand or do next? What in the composition or content belongs to this subject? Check whether emphasis, grouping, type, imagery and feedback support those answers. For generic UI, use [Polish](Polish.md) to diagnose a repeated decision and its visible cost. For interactive work, exercise the relevant task, recovery, input or reduced-motion state and reuse matching behavioral tests. Use the [content fixtures](CollectEvidence.md#stress-content) when data could change the verdict. Playback, focus movement and task completion need direct evidence.
4. **Return findings the owner can act on.** For each material issue give the route or page, state and location, the full evidence path and relevant detail, effect on the person, and smallest correction with a retest. Distinguish observed regressions, existing defects, inference and taste. If a required capture or runtime check is blocked, report exactly what is missing and limit the verdict to what you could inspect.

If edits are authorized, repair the cause under the owning flow. Repeat the matching capture and interaction checks on the revised artifact and adjacent states. Deliver the requested entry point or files, editable sources when needed and reviewable originals.
