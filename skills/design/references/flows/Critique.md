# Critique visual work

Use for a visual review or as a separate pass after initial inspection of substantial visual work. Review the actual preview, recording or export in its intended medium against the brief, relevant reference, baseline and project conventions. If a needed artifact or runtime is unavailable, say what the available evidence can establish and leave the rest unverified.

## Load the deliverable's format

For a deliverable review, select the matching guide from the [format index](../formats/README.md), then open and read that guide before choosing cases or writing findings. The index only points to the review criteria. Match the deliverable, even if the available evidence is a screenshot, export, or handoff note. Open a second format guide only if a separate part of the deliverable needs different checks.

Tool guides are optional. Open one only if you need its instructions to collect or verify evidence; use evidence and tools already sufficient for the review. When reviewing a change, compare matched before and after states and distinguish introduced problems from existing ones.

## Inspect and report

1. **Pick cases that could change the verdict.** For UI, see a primary task with realistic content plus the width, input or adverse state most likely to break it. For a system or theme, compare representative components in the affected states. For an asset or slide, view the actual export at intended scale and an important crop or background. For motion, try normal use, interruption or repeated use and reduced motion when applicable.
2. **Inspect purpose and use.** Check whether the right thing leads, important actions and states are legible, and the result holds across conditions that matter. To reproduce data stress, use [Collect Evidence](CollectEvidence.md) for valid extremes and representative fixtures. Reuse [Test](../../../test/SKILL.md) evidence for repeatable behavior, accessibility checks or measurements. A static image cannot establish live behavior or accessibility.
3. **Make each finding actionable.** Give the location or condition, evidence, consequence and the smallest useful next step. Separate observed defects, inferences and matters of taste. Show what changed and what nearby work might be affected. Name conditions you could not inspect.

Review-only work ends at findings. If corrections are authorized, pass findings to the owning flow, recheck the actual changed result and include normal and adverse cases for stress-related corrections. Finish with the requested files or entry point, editable sources if needed, and any remaining material limits.
