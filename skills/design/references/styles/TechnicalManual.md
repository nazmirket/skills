# Technical manual

Use the visual language of a service manual when someone needs to inspect an object, follow a process or recognize the part that changed. Begin with verified geometry, a real sequence or an actual data path.

Use a keyed diagram or annotated product view where it answers a question. Give labels a stable reference edge, reserve one emphasis color for the current part or step, and number items only where the sequence or cross-reference needs it. Use available space for the instruction, unit, limit or consequence. Keep explanatory leaders visibly separate from clickable controls.

**Try it.** Show how to change the pen in a desktop plotter. Use its actual assembly to identify the holder, latch and insertion depth. Pair one drawing with a short ordered procedure. Collapse the layout to phone width and confirm that each step still identifies its part. If the assembly is unknown, label the drawing as a concept until someone can check the fit.
