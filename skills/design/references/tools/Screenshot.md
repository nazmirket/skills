# Screenshot capture

Use to make an observed visual state reviewable. Prefer the target's own capture tool: a browser for a web page, the app or simulator for its own surface. Use a window, region, or desktop capture when the surrounding UI is essential or a target-native capture cannot show it. Respect host capture permissions and keep unrelated windows, private data and notifications out of the frame.

1. Reproduce the state first. Capture at the intended viewport, zoom and device scale. For comparisons, match content, state, dimensions, theme, and scroll position. If a necessary difference changes the comparison, name it.
2. Match coverage to the review. For a whole landing page or other long surface, capture from top to bottom at a representative width. Let lazy content load first. Use a full-page image, or ordered overlapping sections if the tool cannot capture the whole surface reliably. Add the relevant viewport or scroll state for fixed elements, clipping, or responsive issues that a full-page image can hide.
3. Make every finding readable. Keep the original capture at a resolution that preserves text and layout details. Use a higher device scale or a separate unshrunk detail capture when the review viewer makes the overview illegible. Label details with the section, viewport, and state; keep enough surrounding context to locate the problem. A local issue may need only a viewport or region.
4. Open the saved images at the size the reviewer will use. Check coverage, content, crop, resolution, and overlays. Hand off their paths with the target, revision or build, browser or app, viewport, state, and reproduction steps. Call out any missing section or state. Put disposable captures in the [project scratch area](../../../execute/references/Workspace.md); use the requested destination for a delivered image.

If a capture is blocked, try a permitted target-native alternative or state the gap. An image establishes appearance at one state. Use runtime evidence for navigation, keyboard access, gestures, animation, or performance. For Playwright encoding and capture options, see its [screenshot guide](https://playwright.dev/docs/screenshots).
