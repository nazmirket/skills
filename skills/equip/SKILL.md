# Equip

Equip owns the recommendation to keep, adjust, pilot or replace a tool or format. [Search](../search/SKILL.md) supplies external evidence, [Debug](../debug/SKILL.md) investigates incorrect behavior and [Architect](../architect/SKILL.md) decides shared abstractions.

## Check fit

- Identify the outcome, hard requirements and project conventions. For an unspecified routine choice, use the established tool when it fits. Depart only for a material improvement.
- For recurring friction, check supported extensions and simpler capabilities already in the project before adding a workaround. Compare with one credible outside option using current evidence. Stop exploring when the existing stack meets the requirements. Explain a mismatch that changes the recommendation.
- If a requested tool or format fails a hard requirement, identify what would be lost and recommend an option that preserves the outcome. Wait for approval before substituting it. Continue preparation common to both.

## Recommend the next step

For uncertain benefits, report the measured cost of staying or the missing baseline. Explain the alternative's potential benefit. Propose a representative pilot, success threshold and expected effort. Run it only under existing or newly granted authority.

Compare results on the same workload and requirements. Weigh observed gains against setup, compatibility, migration, rollback and ongoing ownership. Use [Test](../test/SKILL.md) for specialist comparisons. Confirm authority before a material switch, cost or expansion of access or data sharing.

Give [Preflight](../preflight/SKILL.md) the chosen tool, environment and required capabilities. Preflight verifies basic function after separately authorized setup. See [fit scenarios](references/FitScenarios.md) for worked examples.
