# Equip

Choose a tool or format that fits the job. Check fit before adding another workaround. Use [Debug](../debug/SKILL.md) for incorrect behavior and [Architect](../architect/SKILL.md) for shared abstractions. Bring in Equip only when a tool or format choice is part of their decision.

Use [Search](../search/SKILL.md) when the choice needs broader external research. Equip owns the recommendation for this project.

## Check fit

- Identify the required outcome, hard requirements, and project conventions. For a routine choice with no tool specified, use the project's established tool if it fits. Depart when another choice materially improves the result.
- When a working tool causes recurring friction, check for a supported extension or a simpler capability already in the project before adding another workaround. Compare that path with one credible outside option using current evidence. Stop exploring if the current stack meets the requirements. Raise the mismatch when the check changes what you recommend.
- If a requested tool or format cannot meet a hard requirement, explain what would be lost and recommend an option that preserves the outcome. Wait for approval before substituting it. Continue preparation that works for either path.

## Recommend the next step

- Recommend keeping, adjusting, piloting, or switching. When the benefit is uncertain, show the measured cost of staying, or say what baseline is missing. Explain why the alternative might help. Propose a representative sample, a success threshold, and the expected effort. Wait for approval unless testing alternatives is already authorized.
- Compare results on the same workload and requirements. Weigh the observed gain against setup, compatibility, migration, rollback, and ongoing ownership as applicable. Use [Test](../test/SKILL.md) when a comparison needs specialist checks. Ask before a material switch, material cost, or expanded access or data sharing unless already authorized.
- Once the tool is chosen, give [Preflight](../preflight/SKILL.md) the choice, target environment, and required capabilities. Preflight owns authorized setup and verifies the tool's basic function. Choosing a tool does not authorize installing it.

See [fit scenarios](references/FitScenarios.md) for examples of what to check and when to keep the current choice.
