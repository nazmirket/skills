# Equip fit scenarios

Use these cases to recognize the mechanism of a mismatch. Each situation is hypothetical; the recommendation depends on its stated constraints. Check real evidence before applying it to another project.

| Working choice | What to challenge and try | Evidence or reason to keep it |
| --- | --- | --- |
| **1. XLSX as a transport envelope.** Two unattended jobs exchange one flat table nightly; neither needs formulas, formatting, or multiple sheets. | Compare CSV with an explicit schema, encoding, and null convention. Consider JSON if the records are nested or the receiving contract calls for it. Compare actual file sizes instead of assuming which format is smaller. | In an authorized pilot, round-trip representative rows through both consumers, including IDs with leading zeros, dates, delimiters, and missing values. Keep XLSX when a consumer requires it or relies on workbook features. |
| **2. An opinionated UI kit for a highly custom interface.** The screen works by overriding library internals and patching markup after upgrades. | Identify the work spent undoing the library's defaults. Compare a supported extension in the existing library with a lower-level primitive that provides the behavior without prescribing the appearance. [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction) is an example to assess when it fits. | If the supported extension still falls short, propose piloting the hardest component. Compare customization effort and control, and require equivalent keyboard and focus behavior. Keep the current kit where its defaults fit; avoid rewriting unrelated components. |
| **3. Loading a whole dataset for a selective query.** A pandas script reads all columns of large Parquet files and filters to a few columns and rows. It finishes, but does work the result may not need. | Check column selection and supported filters in the current stack. In parallel, check whether one alternative such as DuckDB supports the needed inputs and outputs. Stop if tuning meets the requirements. [pandas scaling guidance](https://pandas.pydata.org/docs/user_guide/scale.html), [DuckDB Parquet support](https://duckdb.org/docs/stable/data/parquet/overview). | If tuning falls short, propose a pilot with representative data, identical results, and target limits for peak memory and elapsed time. Keep the tuned baseline if a new engine adds more operational cost than the measured gain warrants. |
| **4. An AST rewrite that discards source details.** A codemod produces correct Python, but the diff loses comments and alters formatting that must be preserved. | Choose a representation that retains source details. For Python, [LibCST](https://libcst.readthedocs.io/en/latest/) is an example; verify support for the project's syntax. | Propose a pilot with one representative file. Verify behavior and inspect the diff for changes beyond the intended edit. Keep an AST for analysis or for transformations where the source details do not matter. |
| **5. Replacing an ORM to fix excess queries.** An orders page renders, but it loads each order's customer in a separate query. The user wants a new ORM. | Check the loading strategy first. Try the existing ORM's supported eager-loading options for the relationship. [SQLAlchemy relationship loading](https://docs.sqlalchemy.org/en/20/orm/queryguide/relationships.html). | Compare query count and returned rows, including pagination and repeated customers. Adopt the smaller change if it fixes the query pattern without creating a new problem. |
| **6. Splitting CSV on commas.** A hand-written parser works on current exports, but the producer can emit quoted delimiters and multiline fields. | Use a standard CSV parser configured for the producer's dialect. [Python CSV handling](https://docs.python.org/3/library/csv.html). | Exercise a quoted comma, an escaped quote, and an embedded newline. A simple split is sufficient only if the input contract really excludes those cases. |
| **7. Click automation for a data export.** A daily browser job downloads files successfully, but layout updates require repairs. A supported API may expose the same data. | Check the API's authorized scope, filters, pagination, and rate limits. If it covers the job, propose a pilot on a small export. | Reconcile the exported records and fields with the UI. Keep browser automation for operations that require the UI or lack a supported equivalent. |
| **8. A server runtime for a static site.** A docs site runs an app server even though its pages can be built ahead of time. | Check for runtime needs such as authentication, request-time content, or redirects. If the deployable artifact is fully static, compare serving the export with the existing web server. | Verify routes, assets, navigation, caching, and real 404s. Keep a runtime where it provides required behavior that static hosting cannot replace. |
| **9. A workbook that serves the whole job.** People review formulas, annotate sheets, and approve an XLSX workbook. An automated consumer would prefer JSON. | Keep the workbook for review. Consider a separate structured export if automation needs one, with a clear source of truth. | Verify the export matches the approved values and preserves identifiers. The human review and approval steps are part of fit. |
| **10. A faster library with an unjustified migration.** The supported incumbent passes the required cases and runs a small weekly job. A competitor could run it faster, but the replacement changes several interfaces. | Compare the value of the improvement with compatibility work, migration risk, and future maintenance. Recommend keeping the incumbent if the benefit is immaterial. | Revisit if workload, latency requirements, or support changes enough to tip the decision. Record the threshold when known. |

For a new task with no chosen tool, start from the job rather than the catalog. For example, to publish a docs site, find out what must be served at request time and check the project's existing build and hosting before selecting a stack.

When a needed capability is absent, separate the proof from the workaround. An HTTP request can establish that checkout responds, but it cannot establish keyboard operation. Use [Preflight](../../preflight/SKILL.md) to check browser availability and verify basic function after authorized setup. The verification owner exercises the actual interaction. When a chosen test runner needs setup, give Preflight the choice and requirements. It owns authorized setup and checks that the runner can execute a representative test.
