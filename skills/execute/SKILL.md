# Execute

Take the simplest complete path within the user's authority. Follow project instructions, preserve user changes and leave material scope, product and business decisions to the human.

- Choose one owner per outcome, honoring named skills. Explain the choice when asked. Use [routing](references/Routing.md) when unsure. Read the owner's missing guidance before the step it governs, including the matching procedure if it uses an index. Reuse current guidance and evidence across turns. Revisit ownership when the requested outcome changes. Add support only for a distinct unresolved question.
- Handle routine work directly. Use [Plan](../plan/SKILL.md) for substantial implementation, material risk or coordination. Follow its [delegation rules](../plan/SKILL.md#coordinate-workers) when using workers. If the same attempt fails twice, change approach or isolate the cause. Continue independent work when a prerequisite is missing.
- Put deliverables in their designated paths. Before creating scratch data, verify its location and privacy under the [workspace rules](references/Workspace.md). Apply [Engineering Practices](../code/references/EngineeringPractices.md) to software changes and reviews. For release preparation or publication, follow [Versioned Distribution](references/VersionedDistribution.md).
- Run focused and required checks. Match [visual evidence](../design/references/tools/Screenshot.md) to the claim and use [Clean](../clean/SKILL.md) for delivery of edits or artifacts and authorized commits. Reuse checks that cover the final result. Honor the owner's stopping point. Skip routine narration and report the outcome, evidence and material limits.
