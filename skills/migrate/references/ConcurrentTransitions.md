# Concurrent state transitions

Use when old and new consumers must coexist or writes continue during a state transition. Prefer an authorized pause and one transition when those satisfy the requirements. Keep [Migrate's preservation, authority and recovery rules](../SKILL.md); this guide supplies the compatibility sequence.

1. **Map the overlap.** Identify active application versions, background jobs, external writers and rollback versions. Record which representation each reads and writes in every phase. Choose the authoritative data and the compatibility window before implementing synchronization.
2. **Expand compatibly.** Add the representation and compatibility path before any consumer requires them. Keep old consumers working during the overlap. Inspect the installed database's locking, rewriting and constraint behavior; an additive schema change can still block traffic. Use the matching [Code guide](../../code/references/README.md) when engine-specific behavior is unresolved.
3. **Preserve concurrent changes.** Establish how inserts, updates and deletes reach the target before copying existing data. Use the project's supported transactional write path, change capture or synchronization mechanism. Account for partial failures and ordering; two independent writes are not automatically consistent. A stale backfill must not overwrite a newer value or recreate a deleted record. If the mechanism cannot preserve the contract, resolve that gap or use an authorized write pause.
4. **Backfill with bounded, repeatable work.** Use stable identifiers, limited batches and progress that can be checked against committed data. Record a checkpoint only for completed writes and make replay after a crash safe. Keep long-running migration logic compatible with the versions that may run during it. Observe load, contention and failures; throttle or stop at the agreed limits. Queuing all batches does not establish completion.
5. **Catch up and compare.** Define the snapshot or write boundary against which reconciliation is meaningful. Account for changes during the copy and any remaining lag. Check missing, duplicate, changed and deleted records plus the preservation invariants; equal totals alone cannot establish equivalence. Require the completed data and compatibility evidence before switching a consumer that depends on them.
6. **Switch consumers and close the overlap.** Give [Deploy](../../deploy/SKILL.md) the compatible application/state combinations and the verified switch point. Verify real reads and writes after the authorized switch. Retire the old representation and synchronization only under [Migrate's existing retirement and recovery criteria](../SKILL.md#rehearse-and-execute).

Rehearse the consequential races in isolation: interrupt and replay a batch, update a record after it was read for copying, and delete a record while it is being copied. Compare the final state with the agreed mapping and write order. Report the remaining consumers, lag, failed records and current recovery position.

Choose checkpoint and batch limits supported by the actual store and release process.
